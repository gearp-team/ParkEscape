## 결론

- **파격안 가운데 살아남은 것은 차 방탈출(W1) 하나다.** 4.20점으로 I13(4.29)과 0.09점 차이라 사실상 동점이고, 묶음 B-A(4.09)보다 높다. 시연 가능성(5점)과 개인정보(5점)는 6개 가운데 가장 좋다. 퍼즐 신호 13개가 모두 Virtual Console 카드로 바뀌어 가짜 데이터 없이 시연되고, 위치·주행 데이터를 전혀 쓰지 않기 때문이다. 깎인 곳은 창의성(3점)이다. Tesla가 2019년에 핸들·브레이크를 입력으로 쓰는 게임을 양산했다는 사실이 검증 단계에서 드러났다.
- **나머지 셋은 기존 후보보다 낮다.** 차의 다마고치(W2, 3.69)는 쓰려던 API 두 개가 기대와 다르게 동작하고 같은 개념의 보험사 특허가 있다. 경로 맞춤 오디오 가이드(W4, 3.29)는 핵심 장면을 에뮬레이터에서 재현할 수 없어 시연 점수가 2점이다. 와이퍼 크라우드 날씨(W3, 2.80)는 Ford·Audi가 이미 상용화했고, 위치를 서버로 모아야 해서 데이터 리스크가 1점이다.
- **심사 점수는 안정적이다.** 다시 채점한 I13과 B-A가 지난 심사(4.31, 4.10)와 0.02점 안에서 같게 나왔다.

## 아이디어별 경쟁 사례와 심사평

### W1 차 방탈출: 차 전체가 게임 패드 — 4.20

충전·주차로 서 있는 동안 깜빡이·등받이·창문·실내 조명·공조를 직접 조작해 단서를 푸는 방탈출 게임이다. 앱은 차를 제어하지 않고 사람이 조작한 결과를 읽기만 한다.

**경쟁 사례**
- Tesla Beach Buggy Racing 2(2019-06): 실제 핸들과 브레이크를 입력으로 쓰고, P단에서만 작동하며, OTA로 고객 차량에 배포된 양산 기능이다. 2026년 현재도 제공되는지는 확인하지 못했다(wow-benchmark-01, 반박 후 정정).
- Ford Mustang Mach-E 방탈출(2022-01): 작동하는 콘셉트이고 양산 근거는 없다. 게임이 전동 시트·테일게이트·공조·헤드라이트를 작동시키는 방식이며, Ford는 충전 대기와 차 기능 학습을 용도로 들었다.
- BMW·MINI AirConsole(2024-08): 정차 중 게임이 50만 대 이상에 OTA로 배포됐다. 폰이 컨트롤러이고 차는 화면이다. 이용자 수·이용 시간은 공개되지 않았다(-02).
- holoride(2024-05 파산 신청): 별도 VR 하드웨어를 요구한 인카 엔터의 유료화 실패 선례다.

**남는 차별점:** 차량을 제어하지 않고 차 전체(신호 13개)를 입력으로 읽는 구조, 충전 시간에 맞춘 판 길이, 좌석 점유 기반 동승자 협동 모드. 기획서에는 "Tesla가 정차 중 게임 입력으로 양산했고 Ford가 기능 학습용 콘셉트로 시연한 방향을, 차량을 제어하지 않는 읽기 전용 신호로 개방형 앱마켓에서 구현한다"고 쓴다.

**심사평**
- 공모전(4.00): 차량 신호가 없으면 앱이 성립하지 않아 차량특화·기술활용은 만점이다. 창의성은 선례 때문에 3점이다. 사업성은 한 번 푼 퍼즐을 다시 할 이유가 약해 테마 공급에 기대고, 충전 대기 규모와 인카 게임 이용 실적이 확인되지 않아 3점이다.
- 구현(4.50): 신호 13개가 모두 API_INDEX에 있고 퍼미션은 모두 normal이며 제어(set)를 쓰지 않는다. MVP 퍼즐 5종과 기어·SOC·충전 스위치가 모두 Virtual Console로 바뀐다. 외부 서버가 없다. 대신 퍼즐 상태 기계, 탈출 연출, 테마 콘텐츠로 화면 3~4개 규모다.
- 안전(4.33): 게임은 P(`0x0`)에서만 열리고 기어를 넣거나 규제가 걸리면 바로 숨기고 저장한다. Tesla의 P단 한정 양산 배포가 정책상 받아들여질 근거가 된다. 다만 조회 퍼미션이 6개 도메인(LIGHTS·SEATS·WINDOWS·CLIMATE·DRIVE·ENERGY)에 걸치고, 주차장에서 창문을 열게 하거나 충전소에서 깜빡이를 켜게 하는 콘텐츠는 정책 해석이 필요하다.

**기획으로 가져간다면 먼저 고칠 것**
- "세계 최초"를 쓰지 않고 위의 문장으로 위치를 잡는다.
- 다시 할 이유를 설계한다. 테마 팩 외에 판마다 퍼즐 조합이 바뀌는 방식이나 신차 기능 익히기 모드를 검토한다.
- MVP의 퍼미션 도메인을 줄이고, 창문 열기·외부로 보이는 등화 조작을 요구하는 퍼즐은 빼거나 끝에 원상 복구를 안내한다.
- 충전 대기 시간과 인카 게임 이용 수치는 근거가 없으므로 정성 근거(완성차 채택 흐름)로만 쓴다(-10).
- 앰비언트 색·창문별 area·등받이가 탑재 3차종에서 지원되는지 확인한다.

### W2 내 차가 살아 있다: 차의 다마고치 — 3.69

차 상태와 내 운전이 화면 속 캐릭터의 기분이 된다. 부드러운 제동, 적절한 휴식, 벨트 착용, 소모품 관리가 캐릭터를 건강하게 키운다.

**경쟁 사례**
- NIO NOMI: 감정 엔진을 내세운 대시보드 위 캐릭터지만 공식 설명상 음성 비서다. 운전·차량 상태를 기분으로 반영한다는 설명은 없다(-03).
- 다마고치형 제품은 검색한 범위에서 찾지 못했다. 하지만 Allstate 특허 US9858832B1(2018 등록)이 운전 데이터로 캐릭터의 건강·행복 같은 속성을 바꾸는 개념을 담고 있다(-04, 불확실).
- 점수·배지형: Tmap 운전점수 UBI 가입자 500만 육박, 캐롯 멤버스 오토(등급 5단계·레벨 1~30). 21개월 추적 연구(운전자 175명)에서는 점수표의 효과가 가장 컸고 게임화가 두 번째였다.

**심사평 요점**
- 브레이크는 눌림 여부만 줘서 "급제동" 판정에 맞지 않다. `Tire.getLowTirePressure`는 현재 저압 여부가 아니라 저압 기준값(kPa)을 돌려줘서 "타이어 저압이면 캐릭터가 절뚝임"을 구현할 수 없다.
- 캐릭터 상태 4개 중 2개(안전벨트, 워셔액·오일)는 Virtual Console 카드가 없어 가짜 데이터로 시연해야 한다.
- "브레이크 횟수가 적으면 기쁨" 규칙은 필요한 제동까지 줄이게 만드는 유인이 될 수 있다. Lifestyle은 주행 중 예외 카테고리가 아니어서 주행 중 아이콘 표시도 해석이 필요하다.
- "점수표는 금방 질린다"는 전제가 효과 연구와 맞지 않는다.

### W4 길이 들려주는 이야기: 경로 맞춤 오디오 가이드 — 3.29

지나가는 장소의 역사·전설·숨은 이야기가 그 지점을 지나는 순간에 맞춰 흘러나온다. 아이가 타면 아이용 이야기로 바뀐다.

**경쟁 사례**
- Autio: 스토리 25,000개 이상, 2026-08 Ford·Lincoln 5개 차종 대시보드에 들어갔다. Mercedes는 아우토반 Tourguide를, 한국관광공사는 오디를 운영한다(-09, 불확실).
- holoride는 내비가 계산한 여정 시간에 맞춰 콘텐츠 길이를 바꾸는 elastic content를 내세웠고, 남은 이동 시간에 맞춰 오디오를 고르는 특허도 2008년부터 있다.
- 남는 차별점은 "내비 경로상 개별 지점 도착 시각에 이야기 끝을 맞추는 재생 스케줄링" 하나다.

**심사평 요점**
- NaviHelper의 주행 정보는 남은 거리만 주고 경로 모양 API가 없어, 지점 도착 시각은 위치와 heading으로 추정해야 한다.
- 에뮬레이터에서 위치 이동과 TBT 이벤트가 나오는지 실측 전이라 차별점 장면을 가짜 위치로만 시연할 수 있다(시연 2점).
- Music/Audio 필수 요건(MediaBrowserService·MediaSession·오디오 포커스), 녹음 콘텐츠, 서버, 위치 동의가 모두 필요하다. 대신 주행 중 조작은 카테고리 규칙에 그대로 맞아 정책 점수는 5점이다.

### W3 모든 차가 기상 관측소: 와이퍼 크라우드 날씨 — 2.80

와이퍼 단계·안개등·김서림 방지 신호를 익명으로 모아, 내 경로 앞 "3km 앞 비 시작" 같은 도로 위 초국지 날씨를 알려 준다.

**경쟁 사례**
- Ford Local Hazard Information(2020-01, 유럽): 와이퍼·안개등·에어백·비상등 신호를 쓰고, HERE가 여러 브랜드의 정보를 모은다(-06, 확인). Audi도 비·조명 센서와 와이퍼를 쓴다. Mercedes의 폭우 경고는 공식 데이터 상품 페이지에는 와이퍼 트리거가 없고 보도에는 있다.
- Toyota×Weathernews(2019)와 기상청 차량 OBD 수집(2016)이 실증으로 있었다. 국내 공공 상용 서비스는 찾지 못했다(-07).
- 근거 통계: 우천 치사율이 맑은 날의 약 1.3배(전국 2023~2025), 1.4배(고속도로 2021~2025)다(-08, 미검증).

**심사평 요점**
- 차별점이 "개방형 앱마켓·국내 도로"라는 배포 방식뿐이다. Pleos 탑재 규모가 작아 네트워크 효과가 생기기 전에는 초기 가치가 약하다.
- 경로 모양 API가 없어 "내 경로 3km 앞" 판정은 근사다. 다른 차의 관측은 서버에 넣은 가짜 30대로 시연해야 한다.
- 위치와 차량 신호를 서버로 모아 집계하고 외부에 파는 구조라 외부 전송 범위가 6개 중 가장 넓고, 위치기반서비스 신고와 제3자 제공 동의가 필요하다.

## 선택지 비교: 재출발 체크 vs 차 방탈출

| | 재출발 체크(I13) → 장거리 쉼표(B-A) | 차 방탈출(W1) |
|---|---|---|
| 핵심 순간 | 휴게소에서 다시 출발할 때 | 충전·주차로 서 있을 때 |
| 심사에 거는 이야기 | 안전과 가족(아이를 두고 출발하지 않게) | 놀라움과 재미(차가 통째로 게임 패드) |
| 2차 PT 시연 | 뒷좌석을 비우고 브레이크를 밟으면 경고(4점) | 깜빡이·창문·공조를 조작하면 퍼즐이 풀림(5점) |
| 확인된 차별점 | 순정 후석 알림은 하차 시점만 다룬다(competitor-benchmark-03 ✅) | 제어 없이 차 전체를 입력으로 읽는 구조. 단, Tesla·Ford 선례가 있다 |
| 약점 | 페인포인트 통계 없음, 이용 빈도 낮음 | 다시 할 이유가 약함, 조회 퍼미션 6개 도메인, 퍼즐 콘텐츠 제작 |
| 개인정보 | 탑승·구간 기록의 저장 범위를 정해야 한다(4점) | 위치·주행 데이터를 쓰지 않는다(5점) |
| 공통 리스크 | 뒷좌석 좌석 점유가 탑재 3차종에서 지원되는지 미확인 | 앰비언트·창문 area·등받이가 탑재 3차종에서 지원되는지 미확인 |

점수로는 둘이 동점에 가깝다. 고르는 기준은 심사위원에게 어떤 첫인상을 남기고 싶은지다. 파격을 원하면 W1이 이번 탐색의 결론이다. 시연이 가장 강하고 개인정보 부담이 가장 작다. 안정적인 문제 해결형 이야기를 원하면 기존 추천(I13 MVP, B-A 비전)을 그대로 쓴다.

## 이번 비교의 한계

- 파격안 4개는 메인이 직접 쓴 카드라 관점별 발상 → 정리 단계를 거치지 않았다. 같은 방향의 변형안은 비교하지 않았다.
- 경쟁 조사는 검색으로 찾은 범위다. "찾지 못했다"는 "없다"는 뜻이 아니다. 특히 현대·기아·제네시스 국내 차량에 비슷한 기능이 있는지는 한국어 검색으로 확인하지 못했다.
- Allstate 특허(W2)와 elastic content 관련 특허(W4)의 청구항이 겹치는지는 검토하지 않았다.
